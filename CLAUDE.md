# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

**Aim Trainer**: a personal aim trainer, focused on **tracking** (KovaaK's-style) that records detailed per-run metrics so a plateau can be diagnosed: lag vs. lead, speed matching, reaction to direction changes, left/right asymmetry, fatigue. Every run is stored for later analysis, including by an LLM. Specs live in `spec/`; `spec/000-index.md` is the index.

## Stack

- **Framework:** TanStack Start + React 19, Vite 7, `@cloudflare/vite-plugin`
- **Runtime/Deploy:** Cloudflare Workers
- **Database:** D1 + Kysely (`kysely-types.ts` generated by `pnpm db:types`). Raw per-frame samples in `session_samples` (same DB).
- **Validation:** Zod v4. Shared schemas live in `src/common/lib/tracking.ts`, and stored JSON is parsed through them, never cast.
- **Styling:** Tailwind v4, tokens in `app.css` `@theme`
- **IDs:** ULID (`ulidx`). **Timestamps:** ISO-8601 strings.
- Framework versions are pinned to tomcode's working set. Latest `@tanstack/react-start` needs Vite 8, so don't bump it on its own.

## Architecture

Domain-driven: `src/domain/<name>/{components,services,validators,types}`, each with an `index.ts` public surface. **Domains never import each other.** Routes compose them, and cross-domain types go in `src/common/lib/`.

- `trainer` — scenarios, seeded mover, camera/projection/renderer, `TrainerView` (pointer lock, fixed-step physics at 1/480 s, per-frame sampling). `TrainerView` plays a `Drill`: a Pure Aim scenario or a Recoil Control drill. Weapons and their (approximate) spray patterns are in `services/weapons.ts`.
- `analysis` — `computeSummary`, `diagnose`, `downsample`, `buildReport`, `computeRecoilSummary`, `diagnoseRecoil` (all pure), `ResultsPanel`, `RecoilResultsPanel`
- `sessions` — server fns (`saveSessionFn`, `listSessionsFn`, `getSessionSamplesFn`; recoil: `saveRecoilSessionFn`, `listRecoilSessionsFn`, `getRecoilShotsFn`), `HistoryPage`, `AccuracyChart`
- `settings` — degrees per mouse count: `YAW[game] × sens` for presets (no DPI needed), `cm/360 + DPI` only for custom. Stored in localStorage (per device).
- `hearing` — footstep audio trainer (SPEC-005): stereo Web Audio engine, synthesized footsteps (+ optional `public/samples/{concrete|metal}-N.{wav|ogg}`), distractors, adaptive difficulty, `HearingPage`. Trials in D1 `hearing_trial`; prefs in localStorage.

No `as` casts (ESLint `consistent-type-assertions: never`). The single allowed site is `src/server/env.ts`.

## Analysing the player's data

Key metrics are real columns on `session`, and the full `Summary` is in `summary_json`:

```bash
pnpm wrangler d1 execute aim-trainer --local --command \
  "select scenario_id, started_at, accuracy, steady_accuracy, turn_accuracy, lag_deg, velocity_match, reaction_ms, jitter_deg_s, deg_per_count from session order by started_at"
```

Recoil Control runs (SPEC-006) are in `recoil_session` (`drill_id`, `hit_rate`, `vert_comp`, `horiz_comp`, `vert_bias_deg`, …), with the shot log in `recoil_shots`.

Metric definitions are in `spec/phases/p0/001-tracking-trainer.md` and in `METRIC_GUIDE` in `src/domain/analysis/services/report.ts`. The History page's "Copy LLM analysis prompt" button produces the same report.
